# AI Assistant

AI Assistant is a FastAPI service for retrieval-augmented generation (RAG). Upload supported documents, ingest them into a PostgreSQL/pgvector store, and ask a local Ollama model questions using the stored content as context.

## Current Features

- Document uploads for `.pdf`, `.doc`, `.docx`, and `.txt` files
- SQL file uploads to `data/sql/` for database setup and maintenance
- Document chunking, embeddings, vector search, and local LLM responses
- Ollama models for embeddings, reranking, safety checks, and generation
- PostgreSQL with pgvector for vector storage
- FastAPI validation, global error handling, CORS, request IDs, and rotating logs
- Swagger UI, ReDoc, and an OpenAPI schema generated by FastAPI
- Unit and endpoint tests with pytest

## Requirements

- Python 3.12 or later
- PostgreSQL with the `vector` extension
- Ollama, with the models configured in `common/constants.py` available locally
- pip and a virtual environment

The default local models are `nomic-embed-text:latest`, `llama3.2:3b`, and `llama-guard3:1b`. The local reranker is `BAAI/bge-reranker-v2-m3` and may be downloaded by its model runtime.

## Installation

```bash
cd ai_app
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Install and start Ollama separately, then pull the models used by the application:

```bash
ollama serve
ollama pull nomic-embed-text:latest
ollama pull llama3.2:3b
ollama pull llama-guard3:1b
```

Create a PostgreSQL database and enable pgvector. The schema used by the application is in [`data/sql/ai_app_schema.sql`](data/sql/ai_app_schema.sql).

## Configuration

Settings are loaded from environment variables and an optional `.env` file in the project root. Database values are required for ingestion and RAG queries:

```dotenv
APP_NAME=
DEBUG=
HOST=
PORT=

DB_HOST=
DB_PORT=
DB_USER=
DB_PASSWORD=
DB_NAME=

CORS_ORIGINS=
CORS_ALLOW_CREDENTIALS=
CORS_ALLOW_METHODS=
CORS_ALLOW_HEADERS=

MAX_UPLOAD_SIZE_MB=
UPLOAD_TIMEOUT_SECONDS=
LOG_LEVEL=

# Optional integrations
GEMINI_API_KEY=
OPENAI_API_KEY=
```

The application creates `data/documents/`, `data/sql/`, `data/archive/`, `static/`, and `log/` as needed. Uploaded files are stored under `data/`; do not commit private documents, credentials, or generated logs.

## Run The API

Development:

```bash
uvicorn ai:app --reload --host 127.0.0.1 --port 8000
```

Production-style local run:

```bash
uvicorn ai:app --host 0.0.0.0 --port 8000 --workers 4
```

The API is available at `http://localhost:8000`.

## API Endpoints

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/` | Health response; excluded from the OpenAPI schema |
| `GET` | `/health` | Health response |
| `GET` | `/admin` | List uploaded files and admin status |
| `POST` | `/admin/upload-files` | Upload one or more supported files as multipart form data |
| `GET` | `/admin/ingest/documents` | Embed documents and update the vector store |
| `GET` | `/admin/refresh/database` | Execute the SQL schema refresh when database settings are available |
| `GET` | `/rag?prompt=...` | Retrieve context and generate an answer |

Upload example:

```bash
curl -X POST http://localhost:8000/admin/upload-files \
  -F 'files=@data/archive/test.txt'
```

Ingest documents and query the RAG pipeline:

```bash
curl http://localhost:8000/admin/ingest/documents
curl --get http://localhost:8000/rag \
  --data-urlencode 'prompt=What does the uploaded document say?'
```

The `prompt` query parameter must contain between 1 and 10,000 characters. Responses contain a `status` and either an `response` value or an error detail. Requests receive an `x-request-id` response header; sending that header lets callers provide their own correlation ID.

Interactive API documentation is available at [`/docs`](http://localhost:8000/docs), [`/redoc`](http://localhost:8000/redoc), and [`/openapi.json`](http://localhost:8000/openapi.json) after the server starts.

## Test The Project

Run the complete test suite:

```bash
pytest
```

Run a focused test file or use verbose output:

```bash
pytest tests/test_endpoints.py
pytest -v
```

The test fixtures build the FastAPI app in memory and override service dependencies, so endpoint tests do not require a live Ollama server or PostgreSQL instance.

## Project Layout

```text
ai_app/
├── ai.py                    # FastAPI application factory and app instance
├── common/                  # Constants, RAG, embedding, vector, and validation utilities
├── config/                  # Settings, routes, middleware, lifespan, logging, and exceptions
├── data/                    # Documents, SQL files, and archived input files
├── endpoint/                # Admin, health, and RAG HTTP handlers
├── model/                   # Pydantic response models
├── service/                 # Upload, ingestion, database, and RAG business logic
├── static/                  # Static assets such as the favicon
├── tests/                   # Unit and endpoint tests
├── requirements.txt         # Pinned Python dependencies
└── README.md
```

The application follows a layered flow: endpoints validate and delegate requests to services; services coordinate file, database, embedding, and generation utilities; Pydantic models define API responses.

## Development Notes

- Add endpoint handlers under `endpoint/`, business logic under `service/`, and response models under `model/`.
- Register new routers in `config/routes.py`.
- Add or update tests under `tests/`; use dependency overrides for service-level endpoint tests.
- Keep secrets in `.env` or the deployment environment. `.env` is intentionally not part of the repository.
- Application logs are written to `log/` and use rotating file output.
